4. Learned a little bit about Prisma Schema Language (PSL) syntax. I wanted to learn about how PSL uses newlines to separate items. More specifically, I was curious about how this `enum` translates into a new postgres type:

```prisma
enum BattleStatus {
  PENDING
  IN_PROGRESS
  EVALUATING
  COMPLETED
  DECLINED
}
```

It looks like this in a postgres query:

```sql
CREATE TYPE BattleStatus AS ENUM (
  'PENDING',
  'IN_PROGRESS',
  'EVALUATING',
  'COMPLETED',
  'DECLINED'
);
```

and here's how it may look in our battles table:

```sql
CREATE TABLE Battle (
    status BattleStatus
    /* other stuff */
)
```

or of course this for if prisma is making a migration to our table that already exists:

```sql
ALTER TABLE Battle
ADD status BattleStatus;
```

5. The above stuff lead me to learn about that fact that prisma recommends singular PascalCase, while postgres prefers plural snake_case. So, we can use a `@@map` attribute to fix this.
