# bunpo wizard

1. In a route handler controller, I must explicitly call `return` if returning early, or else everything else in that controller will run below where we want to actually end the cycle.
2. Learned about `type assertions` vs `type annotations` today. Type asserts are basically like saying **trust me bro** (so even though the return signature of jsonwebtoken's jwt.verify is `string | JwtPayload`, we can tell typescript to chill out and trust us that it'll return a JwtPayload. This gives us the all great and powerful `IntelliSense` so we can autocomplete to our hearts content. Yippee.), and type annotations are for strictly saying the value MUST be what we annotate it as. So type annotations won't go over well with `jwt.verify` because its return signature is `string | JwtPayload`, and therefore vscode will scream at us because it can't guarantee what'll be returned from `jwt.verify`. So... we'll go with `type assertions` for creating our decoded token!
3. Actually, no, no we wont' use `type assertions`, because I've discovered that we can instead use a zod schema along with infering a typescript type via z.infer, and then via a cool thing called `Type Narrowing`, which Zod is responsible for, we don't even need to type-assert with our new inferred JwtPayload type. Sweeeeeet. So now by using Zod, instead of having typescript just trust us before runtime, Zod actually checks the real stuff/properties at runtime, and then typescript infers that `payload` is guaranteed to be `JwtPayload`.
4. I still decided to use annotation via this: `const payload: JwtPayload = result.data;` for autocomplete perks haha. And I'm hoping it'll help with readability. We'll see!
