### General learned stuff

- _Classes_: Learned a little bit more about classes today, in particular using `super()` when making an extended class. You have to user `super()` first and pass in all the arguments the parent class's constructor expects in order to setup that parent class. Why? Because it needs to setup those constructor properties on `this` before your child/extended class can start adding its own properties.
- _Classes_: As for methods, if you redefine a method on your child class, it overrides the parent method, and at that point the only way to access the original parent method's logic is via using `super.thenameofthemethod()`. If you never redefined it, however, you can just call that parent method as if it was a normal method on the child class.
- _Classes_: I was confused about why we pass 'message' into `super()`, but we don't pass this.name into `super()`. It's quite simple actually: the Error class constructor needs a passed in arg in order to initially establish this.message, but it doesn't need a passed in arg to establish this.name. (It just initializes it as 'Error' that we can simply overwrite in our child class constructor.)

## Stuff I learned today in Bunpo Wizard Backend

### Important learned stuff

- I got a better understanding of old school stateful sessions, pure stateless JWT based sessions, and the hybrid sessions that use JWT + Refresh tokens (which is a combo of stateful and stateless). The hybrid architecture is great because it greatly lowers the server overhead because you only hit your database once every 15 minutes or so (instead of on every single guarded request via old school stateful sessions). So yea, you get the low overhead benefits of stateless JWTs, but also get to use the stateful refresh tokens so the user doesn't have to keep logging back in, PLUS you can keep those JWT tokens valid for a very short time for higher security.
- I also learned about `Refresh Token Rotation`, which basically just invalidates the old refresh token in your refresh tokens table (and replaces it with a new one) so that a hacker can't use it if the user already did.
