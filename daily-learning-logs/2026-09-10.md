1. I was little confused as to why we `throw` errors in services instead of passing to `next()`, but then realized that services are just normal functions and not middleware haha. So we throw an error in the service, and its controller will then catch that error to then pass on to our global error handling middleware via `next(err)`
2. I learned about `Control Flow Analysis` today at lunch. I wanted to know exactly how `Type Narrowing` actually works with TypeScript. The big example is with a Prisma database query in a service. First of all, typescript knows the shape of something like 'user' because of the Prisma models we wrote! So after the Prisma query, the only thing left for TypeScript to figure out is whether or not 'user' is null or not. That's where we do a quick `if (!user) {...}` check, and TypeScript knows that if at runtime the execution gets past that check, then user CAN'T be `null`, and therefore allows us to write code after the check that treats user as if it isn't `null`.

```typescript

```
