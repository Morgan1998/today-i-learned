**Pinned Stuff**

- Use `select` over `includes` for your Primsa queries so you don't accidentally pull stuff you don't want to pull, like a password hash! Ahhhh!
- `interface`s are best for object shapes. They're nice and clean to read, PLUS you can also use `extends` to have them inherit from other interfaces.
- `type`s, however, are required for using these: `Unions`, `Array Aliases`, `Zod Inferences`, and `Primitives`.

1. Using Namespace Imports for the backend is great for organization (like for my controllers, services, and validators). However, for my frontend it may be better to just use Named Imports so we can get the benefits of tree-shaking. Tree shaking doesn't matter in the backed though because the backend isn't bundled! haha.
2. I've learned a good system for keeping my private routes (routes I put after `router.use(authenticate)`) nice and consistent and orderly. How? By ordering via CRUD operations!! Also make sure to put specific/static routes before parameterized routes. Here's an example:

```typescript
router.post(some public route stuff);
// My authenticate Guardian Angel
router.use(authenticate);

// 1. CREATE
router.post(
  '/battle',
  validate(BattleValidator.createBattle),
  BattleController.createBattle,
);

// 2. READ (List first, then specific IDs. Also, make sure to put specific routes before dynamic routes!)
router.get('/battle', BattleController.listBattles);
router.get('/battle/somespecificbattle', BattleController.getSpecificBattle); // Here's a specific route that I gotta put before the dynamic route.
router.get('/battle/:id', BattleController.getBattle);

// 3. UPDATE
router.patch(
  '/battle/:id',
  validate(BattleValidator.updateBattle),
  BattleController.updateBattle,
);

// 4. DELETE
router.delete('/battle/:id', BattleController.deleteBattle);
```
